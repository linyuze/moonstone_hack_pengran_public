# 联调记录

## 目标

输入任意食材 → 生成菜单 → 选中候选 → 孪生编译动作 → 投料 / 控温 / 出餐 / 清洗，全链路不中断。

## 修复前的断点

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 生成完菜单没有反应 | 提示词要求写全调料，但 Web 校验器只认冰箱里登记过的名字 → 调料判 `missing` → strict 模式整单 `blocked` → 前端过滤掉所有候选 |
| 2 | 选「彩椒」必失败 | 冰箱目录写「彩椒」，料筒与提示词写「甜椒」，没有别名归一 → 主料判缺货 |
| 3 | 菜单克数超料筒容量 | 提示词给 1–250 g，孪生调料筒只收 ≤30 g → `/api/recipe` 400 |
| 4 | 「恢复上次菜单」丢忌口 | 快照重建请求时没带 `mealContext` |
| 5 | 本机没有的食材（牛肉等） | 模型照抄进菜谱 → 孪生找不到料筒 → 400，且没有兜底 |

## 本版修复

1. `validation.ts`：固定调料筒（盐、油、生抽、糖、醋、葱花、蒜末、姜末、蚝油、老抽、鸡精、水）无库存时判 `needs-quantity` 而不是 `missing`。
2. `planner.ts`：补 彩椒/甜青椒→甜椒、马铃薯/洋芋→土豆 的别名归一。
3. `handler.ts`：
   - 提示词给出真实料筒清单与克数区间（主料 1–200 g、调料 1–20 g、水 1–150 g）；
   - 文字违规（禁用食材名、辣味字样）与整单不可执行各重试一次；
   - **料筒能力闸门**：候选里出现非本机料筒的食材即判 `blocked`，触发按真实料筒重写；
   - 仍不可执行时返回**标注清楚的替代方案**（清炒时蔬），保证演示链路不中断。
4. `usePanMenu.ts`：快照带上 `mealContext`，恢复菜单不再丢忌口。
5. `vite.config.ts`：补 `/api/twin` 代理。

## 验证方式

```bash
node scripts/e2e-menu-flow.mjs '[ ["番茄","鸡蛋"], ["彩椒","豆腐"], ["牛肉","洋葱"] ]'
```

脚本走的是真实 HTTP：`/api/menu/generate` → 取第一个非 blocked 候选 → `/api/recipe` →
`/api/simulation?speed=8` → 轮询到 `completed`，并记录动作序列与出餐克数。

## 结果

全部为仿真会话（`speed=8`），真实机械臂未验收。

| 输入食材 | 生成菜单 | 孪生状态 | 出餐 |
| --- | --- | --- | --- |
| 番茄 + 鸡蛋 | 番茄炒鸡蛋 / 蒸蛋羹 | completed 100% | 535.5 g |
| 青菜 + 香菇 | 炒青菜 / 炒香菇 | completed 100% | 267.9 g |
| 土豆 + 胡萝卜 | 蒸土豆胡萝卜片 / 胡萝卜土豆煮汤 | completed 100% | 1036.7 g |
| 豆腐 | 蒸豆腐 / 炒豆腐 | completed 100% | 252.1 g |
| 彩椒 + 豆腐 | 炒豆腐 / 蒸甜椒豆腐 | completed 100% | 506.9 g |
| 牛肉 + 洋葱 | 洋葱炒牛肉 / 清煮洋葱牛肉汤 | completed 100% | 931.8 g |
| 空库存 | 演示兜底：清炒时蔬 | completed 100% | 69.1 g |
| 黄瓜 + 鸡蛋 | 黄瓜炒鸡蛋 / 蒸蛋 | 菜单可用（干净克隆冒烟） | — |
| 番茄 + 土豆 + 香菇（3 道菜） | 番茄炒香菇 / 土豆炒香菇 / 番茄煮土豆 | completed 100% | 1052.4 g |

动作序列示例（牛肉+洋葱）：

```
stop > lid > steamer > dispense > cook > serve > clean > water
```

每一步都有 accepted / completed 回执；出餐质量保持 `unverified`（无出餐相机）。

## 仍未验证

- 真实机械臂的加菜、倒菜位姿未现场标定，`/api/arm/execute` 固定返回 409。
- 温控曲线与传热系数未标定，不能据此判定食品熟度。
- 整机外形为工程示意，未做碰撞、飞溅流体、卫生与成本验证。
